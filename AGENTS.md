# open-bt-rig-interface: agent and contributor instructions

This is the single source of rules for anyone (human or AI agent) working in this
repo. `CLAUDE.md` only points here. Roles and authority (who merges, who releases,
and what agents may not do) are in [`GOVERNANCE.md`](GOVERNANCE.md). In short,
agents never merge, approve, release or take `human-task` work.

The project is an open **hardware + firmware** Bluetooth interface between an
amateur-radio transceiver and a host, carrying CAT serial, PTT (RTS/DTR) and
audio. Read [`docs/requirements/constraints.md`](docs/requirements/constraints.md)
before any design work. The project is **app-neutral**: don't tie any design,
name or protocol to a particular host application.

## Workflow

- **Plan first.** Write the plan (in the issue or the PR description) before changing anything.
- **No change without an issue.** Each issue is one agent-sized task. Work that
  needs a person, hardware or an account is labeled `human-task` and is not for agents.
- **Branch per issue**, named `<type>/<issue#>-<slug>` (for example
  `hw/12-power-front-end`, `docs/1-bootstrap`). Types: `hw`, `fw`, `proto`,
  `docs`, `ci`, `enc`, `research`.
- **PR to `dev`** with `Closes #N`. `dev` is pre-release and the default branch.
- **`main` is for releases only**, updated by a `dev` → `main` PR per release.
  Never commit directly to `main` or `dev` (a ruleset enforces PRs).
- **Signed commits only.** Never use `--no-gpg-sign` or change signing config.
  If signing fails, stop and report.
- Research and decision issues end in a written artifact: a findings doc
  or an ADR in [`docs/decisions/`](docs/decisions/) (copy `ADR-0000-template.md`).
- If an issue's "Verify first" fact turns out false, stop and comment on the
  issue instead of guessing.

## Hardware (KiCad)

- **KiCad ≥ 10.0.6.** [`KICAD_VERSION`](KICAD_VERSION) is authoritative. If you
  save files with a newer KiCad, bump it in the same PR. The documented version
  must match the checked-in files.
- **All KiCad changes go through the Konnect MCP tools** (`mcp__konnect__*`).
  Never hand-edit `.kicad_*` files. Load the `konnect` skill first, then the
  task skill: `kicad-schematic`, `kicad-pcb`, `kicad-library`, `kicad-review`,
  `kicad-manufacture`. For full reviews use the `kicad-design-review-agent`.
- Layout: `hardware/boards/<board>/rev<X>/` per board revision.
  Project-local libraries go in `hardware/lib/{symbols,footprints,3dmodels}/`,
  referenced through project library tables with `${KIPRJMOD}`-relative paths.
- **PCB silkscreen must show:** project name, variant, `${REVISION}`,
  `${ISSUE_DATE}`, "Designed by Reid Crowe, N0RC", and the license mark
  (CERN-OHL-P-2.0). Use text variables and never hard-code the revision. The
  title-block revision must match the `rev<X>` folder and the release tag.
- Fabrication outputs are generated by CI and attached to releases. Don't commit them.

## Parts and sourcing

- **FCC-certified radio modules preferred.** Record the FCC ID and follow the
  module's integration guide (antenna, keep-out area, trace).
- Sourcing: search authorized distributors (e.g. Digi-Key, Mouser, LCSC) with
  whatever tools you have. Never commit credentials. Describe private or
  credentialed tooling only in your untracked `AGENTS.local.md` / `CLAUDE.local.md`.
- Each key part needs at least two sources and an active lifecycle. Record the chosen part and its
  alternates in the relevant ADR or BOM notes.

## Firmware

- Portable logic goes in `firmware/app/`, host-tested in `firmware/test/`. SDK glue goes
  in `firmware/platform/<sdk>/` behind a small hardware-abstraction interface.
- Permissively licensed SDKs and dependencies only.
- **PTT fail-safe is mandatory:** PTT off at boot, on reset, on disconnect and on
  watchdog timeout, plus a maximum-TX timer. Every new code path gets a test.

## Protocol

- The host-device Bluetooth protocol lives in [`protocol/`](protocol/), as a
  versioned spec with golden byte vectors. Changing it means bumping the
  protocol version and updating the vectors.
